# Контекст проекта

Перед задачами об архитектуре и развитии проекта прочитайте
[описание возможностей и архитектуры](docs/PRODUCT_AND_ARCHITECTURE.md).
Проект демонстрирует управление жизненным циклом VM на Go с PostgreSQL и Temporal.
Инфраструктура симулируется отдельным HTTP-сервисом, настоящие VM не создаются.

Команды запуска и проверки находятся в [docs/README.md](docs/README.md).

# Стиль кода

Всегда пишите новый и изменяемый код так, чтобы его мог понять начинающий
разработчик, знакомый с основами Go. Следуйте стилю текущего рефакторинга:

- Используйте имена по смыслу: `machine`, `operation`, `request`, `err` вместо
  неоднозначных `v`, `o`, `r`, `e`. Привычные `ctx` и короткие получатели методов допустимы.
- Показывайте основной сценарий последовательно, сверху вниз. Выделяйте
  самостоятельные этапы в небольшие функции с понятными названиями.
- Разделяйте файлы по задачам. Не вводите дополнительные слои, универсальные
  исполнители и абстракции без конкретной необходимости.
- Разворачивайте длинные структуры и сложные выражения для удобства чтения.
  Предпочитайте явную обработку ошибок и возвраты значений.
- Пишите идентификаторы по-английски, новые поясняющие комментарии и документацию
  по-русски. Объясняйте причины нетривиальных проверок, а не пересказывайте код.
- Не предполагается знание Temporal и распределённых систем: объясняйте границы
  транзакций, повторы, владение ресурсами, Fence и откат там, где они важны.
- При изменении структуры обновляйте маршрут чтения в README.
- Упрощая код, сохраняйте поведение и гарантии отказоустойчивости. Подтверждайте
  рефакторинг тестами; для изменений workflow проверяйте совместимость replay.
