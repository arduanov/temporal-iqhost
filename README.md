## Поднять сервисы

1. Установите и запустите Docker Desktop либо Docker Engine с Compose v2.
2. Откройте терминал в корне проекта — там, где находится `compose.yaml`.
3. Выполните одну команду:

   ```sh
   docker compose up -d --build
   ```

4. Дождитесь завершения команды и откройте **http://localhost:8082**.

Первый запуск скачивает образы и собирает приложение, поэтому требует интернета
и может занять несколько минут. Затем автоматически создаются базы, выполняются
миграции, добавляются ресурсы и выполняются шесть демонстрационных операций.
Админка запускается после подготовки данных. Go, Node.js и отдельный запуск seed
на компьютере не нужны.

| Адрес | Назначение |
| --- | --- |
| http://localhost:8082 | Админка: VM, операции и ресурсы |
| http://localhost:8080 | Temporal UI: workflow и история их выполнения |
| localhost:5432 | PostgreSQL: база `iqhost`, пользователь `iqhost`, пароль `iqhost-local` |

Порты 5432, 7233, 8080, 8081 и 8082 должны быть свободны. Сервисы опубликованы
на локальном компьютере. Это демонстрация с симулятором инфраструктуры:
реальные виртуальные машины на гипервизоре не создаются.

В списке уже есть `demo-gpu` в работе, `demo-stopped` в остановленном состоянии,
`demo-deleted` после удаления и `demo-no-capacity` с ошибкой нехватки CPU.

## Показать успешное создание VM

1. В админке укажите **Инициатор**, например `customer-demo`.
2. На странице **Виртуальные машины** нажмите **Создать VM**.
3. Введите уникальный ID, например `customer-web-01`, и параметры:
   **CPU — 2**, **RAM — 2048 MiB**, **диск — 10 GiB**, GPU не включайте.
4. Нажмите **Создать и запустить**. Откроется карточка операции.
5. Дождитесь статуса **Завершена**. При свободных ресурсах выполнение обычно
   занимает около 10–20 секунд; страница обновляется автоматически.
6. Покажите блоки **Доставка команды** и **Завершённые шаги**.
7. Нажмите ссылку с ID машины. В карточке VM проверьте **В работе**, ноду,
   выделенный IP и диск. Здесь же доступны остановка, удаление и история операций.

При повторном показе используйте новый ID. Если свободных ресурсов не хватает,
остановите ненужную VM или удалите её через админку. Остановка сохраняет диск и IP;
удаление освобождает их после подтверждённого завершения операции.

## Перейти в Temporal и показать pipeline

1. Откройте операцию создания новой VM — из её истории или страницы **Операции**.
2. В блоке **Доставка команды** нажмите **Открыть workflow в Temporal UI ↗**.
   Откроется новая вкладка с конкретным запуском этой операции.
3. Покажите статус **Completed**, тип workflow **Lifecycle** и очередь **iqhost-vm**.
4. Во вкладке **History** покажите диаграмму **Event History**. На ней видны порядок
   и длительность шагов:

   `begin-operation → reserve-resources → create-instance → attach-network → start-instance → wait-ready → finish-operation`.

5. Под диаграммой переключитесь на **Compact**, чтобы просмотреть сгруппированную
   историю. Полная история доступна в **All**, исходные события — в **JSON**.
6. Вернитесь во вкладку админки.

Workflow хранит ход выполнения операции. Статус и ресурсы VM в админке читаются
из PostgreSQL; это позволяет показать и процесс выполнения, и подтверждённый результат.

## Открыть остальные страницы

| Страница | Что показать |
| --- | --- |
| Виртуальные машины | Новая машина со статусом «В работе», поиск по ID, фильтр состояния |
| Карточка VM | Конфигурация, нода, IP, диск, доступные команды и история |
| Операции | Успешная команда создания, подготовленные примеры, фильтры по VM, инициатору и статусу |
| Карточка операции | Результат, доставка команды, завершённые шаги и ссылка в Temporal |
| Ресурсы | CPU/RAM нод, GPU и их владельцы, диски в хранилище, IP-пулы |

Внизу страницы **Ресурсы** раскройте **Адреса и привязки**. Показанные значения —
сохранённые резервы приложения, а не измерения нагрузки оборудования.

## Остановить и запустить повторно

```sh
docker compose down
```

БД, история Temporal и состояние симулятора сохранятся. Для повторного запуска:

```sh
docker compose up -d --build
```

Подготовка не дублирует исходные операции и не сбрасывает изменения, сделанные
во время показа. Текущая БД хранится в `demo-postgres-data`, симулятор —
в `simulator-data`. Прежний volume `postgres-data`, если он есть, сохранён отдельно.

**Только для полного сброса текущего демо:** `docker compose down -v`.
Это удалит его VM, операции, историю Temporal и состояние симулятора.
Следующий обычный запуск создаст исходные демонстрационные данные заново.

## Если запуск не завершился

```sh
docker compose ps -a
docker compose logs --tail=100 demo worker outbox
```

Одноразовые сервисы `migrate`, `seed`, `temporal-setup` и `demo` должны завершиться
с кодом **0** — для них `Exited (0)` является штатным результатом.
Если не запустилась БД или Temporal, посмотрите `docker compose logs postgres temporal`.
При первой подготовке переменная `FAIL_AT` должна быть пустой.
